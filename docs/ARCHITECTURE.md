## Приложение и данные

React/TypeScript обращается к HTTP API по тому же origin. Go обслуживает frontend из `web/dist`, проверяет сессии и CSRF, выполняет операции и запускает фоновые workers. Node.js используется при разработке, сборке и тестировании.

PostgreSQL — обязательное рабочее хранилище: аккаунты, сессии, дела, диалоги, настройки, OAuth state, календарная очередь и уведомления. SQL-миграции встроены в Go и применяются при старте под advisory lock. SQLite сохранена для явного импорта и регрессионных тестов. [Аккаунты и миграции](ACCOUNTS.md).

## Путь команды

В режиме `simple_llm` текст и компактный контекст поступают в GigaChat или Ollama. Модель возвращает intent и типизированные arguments, без идентификаторов записей. Go строго декодирует ответ, рассчитывает даты, разрешает ссылки, проверяет владельца и конфликты.

Неоднозначность приводит к уточнению; удаление и групповые действия требуют подтверждения показанного списка. Перед исполнением проверяется актуальность контекста. Изменение дела, состояние диалога и идемпотентный результат сохраняются транзакционно. Внешний вызов LLM выполняется до транзакции изменения данных. [Контракт runtime](SIMPLE_LLM_RUNTIME.md).

`GENA_NLU_MODE=semantic_plan_legacy` включает прежний путь. Для работы без внешних моделей задаются также `GENA_SEMANTIC_PROVIDER=rules` и `NLP_PROVIDER=rules`. Это режим локального запуска и детерминированных тестов, с отдельными возможностями разбора команд.

## Голос

![Запись, распознавание и ручная отправка](diagrams/voice-flow.svg)

`getUserMedia → MediaRecorder → POST /api/voice/transcribe → Groq → черновик`.

Пользователь проверяет текст и вручную отправляет команду. Аудио обрабатывается в памяти; браузерный SpeechRecognition не используется как автоматический fallback. Groq и GigaChat — отдельные провайдеры с разными ключами и задачами. [Голосовой ввод](DEADLINES_AND_VOICE.md).

## Фоновые процессы

| Процесс | Ответственность |
| --- | --- |
| Reminder worker | Найти наступившие сигналы, сохранить occurrence, поставить доставки в очередь и продвинуть повторение одной транзакцией. |
| Web Push sender | Получить доставки через SKIP LOCKED, отправить зашифрованный push, сохранить результат и повторы. |
| Calendar worker | Отправить изменения через CalDAV, обновить токен и повторить временно неудавшиеся операции. |

Изменение дела и календарная outbox записываются одной транзакцией; CalDAV выполняется вне неё. Направление синхронизации — из Гены в Яндекс. Сервер обрабатывает напоминания и повторения без открытого браузера. [Web Push](WEB_PUSH.md) · [Яндекс Календарь](YANDEX_CALENDAR.md).

## Развёртывание

Многоэтапный Dockerfile собирает React и статический Go binary. Итоговый distroless-контейнер работает без root. Production Compose добавляет read-only filesystem, ограничения ресурсов и отдельную сеть с PostgreSQL. Nginx завершает HTTPS, перезаписывает X-Real-IP и проксирует к loopback-порту приложения.

Локально доступны `/health`, `/docs`, `/openapi.json` и `/architecture`. Production-шаблон Nginx закрывает техническую документацию. [Эксплуатация](../deploy/README.md).
