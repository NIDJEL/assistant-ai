# Проверка тестового задания

[Работающий прототип](https://meinangelplatz.top) · [README](../README.md)

Создайте свой аккаунт. Голосовой ввод: нажмите микрофон, произнесите запрос, остановите запись, проверьте распознанный текст и нажмите отправку. Ответ доступен текстом и по кнопке озвучивания. Текстовый ввод выполняет те же действия. Для микрофона нужен HTTPS или localhost и разрешение браузера.

## Четыре обязательных действия

| Действие | Пример свободной формулировки | Что проверить |
| --- | --- | --- |
| Задача | «Мне бы до конца недели купить билеты» | Содержание и дедлайн сохранены; время не выдумано. |
| Напоминание | «Чтобы не забыть: завтра в десять позвонить Ивану» | Сохранены дата, время и действие. Ивану не нужен аккаунт. |
| Встреча | «Запиши, пожалуйста, завтра в три встречу с Иваном» | Личная встреча сохраняется и для человека вне друзей. Ассистент явно сообщает об отсутствии приглашения. |
| Список | «Что у меня намечается на эту неделю?» | Показаны записи выбранного периода. |
| Поиск истории | «Найди старую задачу про договор» | Поиск включает прошлые записи, учитывает словоформы и поддерживаемые синонимы. |

Если время встречи не названо, ассистент уточняет его. После «Завтра встреча с Иваном» ответьте «В три часа дня»: содержание и дата должны сохраниться. Обновите страницу: созданные данные и диалог остаются.

## История из приложенного CSV

Новый аккаунт пуст. В разделе «Настройки» импортируйте демонстрационные данные; используемый файл `data/voice_assistant_events_1000.csv` совпадает с предоставленным CSV из 1000 записей. Даты исторические, поэтому ищите «за всё время» или по прошлому периоду, а не только среди предстоящих событий. Повторный импорт не должен создавать дубли.

## Контекст, уточнения и подтверждения

- Найдите несколько записей, затем скажите «Вторую перенеси на завтра в 16». Проверьте выбранную запись и сохранение остальных полей.
- После переноса скажите «Нет, лучше в пять»: изменение относится к той же записи.
- «Удали эту встречу» показывает подтверждение. «Отмена» сохраняет запись.
- Неоднозначное имя друга требует выбора; оно не означает приглашение всех совпавших людей.
- Обычная встреча с человеком вне друзей сохраняется лично. Явная просьба отправить приглашение требует добавления человека в друзья. Позднее добавление друга не отправляет старые приглашения автоматически.

## Условия оценки и ограничения

Запуск без ключей по README использует правила и текстовый ввод. Полный режим использует `simple_llm`, GigaChat, Groq STT и настроенное озвучивание. Сетевые ошибки внешних сервисов возможны; интерфейс должен сообщать о них и сохранять возможность повторить действие.

Поиск реализован через русскую нормализацию, нечёткое сравнение и словарь смысловых групп. Он не гарантирует понимание любой перефразировки. Составные запросы, которые невозможно выразить одной поддерживаемой операцией, требуют уточнения. Повторяющиеся встречи и двусторонняя синхронизация Яндекса пока не поддерживаются.

При передаче приватного репозитория заранее предоставьте проверяющим доступ. Ссылку на прототип и права на исходники нужно проверить из отдельной сессии браузера.

## Воспроизводимая проверка свободных формулировок

В `tests/contract/assignment_live_postgres_test.go` находятся 25 небольших сценариев: свободное создание, неизвестные участники, настоящие друзья, приглашения и явный отказ от них, относительные сроки, разговорное время, исторический поиск, синонимы, опечатки, поправки, порядковый выбор и отмена удаления. Проверяется сохранённое действие и его поля, а не только текст ответа. Это регрессионный корпус, который использовался при доработке; он не является независимой оценкой понимания любой речи.

Обычные тесты не вызывают платную модель. Для живого прогона нужны настроенный GigaChat и отдельная одноразовая PostgreSQL на loopback с именем базы, содержащим `_test`. Не указывайте рабочую базу:

```powershell
$env:TEST_DATABASE_URL='postgres://test-user@127.0.0.1:5544/semantic_test?sslmode=disable'
$env:LIVE_SIMPLE_LLM='1'
go test -v -count=1 ./tests/contract -run '^TestAssignmentLiveFreeSpeech$'
```

Каждый сценарий создаёт отдельную схему и тестовые аккаунты, затем удаляет схему. Голосовые браузерные тесты проверяют запись и отправку с подменённым ответом STT. Физический микрофон, качество распознавания в шуме и воспроизведение на конкретном устройстве проверяются отдельно.
