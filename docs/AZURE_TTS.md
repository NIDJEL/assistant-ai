# Голос ответов Гены

Озвучка работает по нажатию существующего динамика. Автоматического чтения нет,
даже если в старых настройках сохранено `tts: true`. Повторное нажатие отменяет
загрузку/воспроизведение; следующий ответ, диктовка и уход со страницы останавливают
предыдущий звук. Секция «Голос ассистента» сохраняет `ttsVoice` и `ttsVolume` через существующий
`/api/preferences/{profile}`. Новых таблиц и профилей нет.

Громкость настраивается ползунком от 0 до 100% (по умолчанию 100%). Значение
сохраняется в пользовательских настройках, применяется к ответам и прослушиванию
голоса, включая уже воспроизводимый звук. 0% выключает звук. Громкость меняется
на стороне проигрывателя, без повторного синтеза и расхода Azure-квоты.

Секреты задаются только на backend:

```dotenv
GENA_TTS_PROVIDER=azure
AZURE_SPEECH_KEY=<secret>
AZURE_SPEECH_REGION=eastus
AZURE_TTS_VOICE=ru-RU-DmitryNeural
```

Пустой provider отключает Azure. При `azure` пустой ключ останавливает запуск с
понятной ошибкой. Нельзя использовать `VITE_*` для секрета. Production использует
root-owned `/etc/rhythm/production.env` (0600) и Compose environment. Перед заменой
конфигурации нужны проверенный backup и сохранённый предыдущий релиз.

`POST /api/voice/synthesize` принимает `{ "text": "Привет", "voice": "ru-RU-DmitryNeural" }`
и возвращает `audio/mpeg`, `Cache-Control: no-store`. Авторизация и CSRF сохраняются.
`GET /api/voice/voices` возвращает только разрешённые русские голоса, присутствующие
в Azure Voice List API выбранного региона. Разрешён только Дмитрий; женские голоса
отклоняются API. Ранее сохранённый выбор женского голоса заменяется на Дмитрия при
чтении настроек. Проверка
доступности кэшируется на 10 минут; ошибку можно повторить кнопкой в настройках.

Синтез: MP3 mono 16 kHz/128 kbit/s, нейтральная интонация, SSML `prosody rate="-5%"`.
Текст экранируется как XML. Markdown-разметка, fenced code, HTML и самостоятельный
JSON исключаются из произношения; даты и время сохраняются для русского голоса.
Ограничение исходного текста — 2000 Unicode-символов, аудио — 4 MiB, запрос к Azure —
20 секунд, вся операция — 25 секунд. 429/5xx не повторяются автоматически.
Сообщения провайдера, ключи и тексты не записываются в логи.

Один процесс обслуживает один синтез одновременно. Лимит пользователя — 12 запросов
в минуту и 6000 исходных символов в день UTC. Общий лимит обращений к Azure —
12000 символов в день UTC (включая неуспешные попытки). Лимиты сбрасываются при
перезапуске процесса и не являются биллинговым ограничением подписки Azure;
для нескольких экземпляров нужен общий ограничитель. Azure quota/budget следует
контролировать в самой подписке.

LRU-кэш: только память процесса, максимум 64 ответа/16 MiB, TTL 15 минут. Ключ —
SHA-256 от полного SSML (включая голос, скорость, текст) и формата. Одновременные
одинаковые запросы используют один результат. Аудио и пользовательские тексты
не сохраняются в файлы, public-директории или persistent cache.

Groq Whisper, GigaChat, NLU и обработка дел не зависят от этого сервиса. Клиент Azure
имеет отдельный transport и не использует Groq proxy.

Локальная браузерная проверка реальных голосов: `AZURE_TTS_E2E=1 pnpm --dir web exec
playwright test e2e/tts.spec.ts`. Нужны приватный Azure credential на backend и
отдельная PostgreSQL в `TEST_DATABASE_URL`. В обычном CI этот тест пропускается;
unit-тесты TTS не обращаются к Azure. Не направляйте полный E2E fixture с импортом
demo-данных на production.
