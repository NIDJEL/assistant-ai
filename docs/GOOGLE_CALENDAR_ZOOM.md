# Google Calendar и Zoom

Обе интеграции подключаются из раздела «Интеграции» к уже авторизованному
пользователю Гены. Они не создают отдельные способы входа и не связывают аккаунты
по совпадению email. OAuth state одноразовый, привязан к браузеру и текущей сессии.
Для Google используется PKCE и offline access; Zoom User OAuth аутентифицирует
backend через HTTP Basic. Токены шифруются AES-GCM с привязкой к пользователю и
провайдеру; ключ выводится из существующего SESSION_SECRET.

## Настройка сервера

Секреты хранятся только в `/etc/rhythm/production.env` (root, 0600):

```
GOOGLE_CALENDAR_CLIENT_ID
GOOGLE_CALENDAR_CLIENT_SECRET
GOOGLE_CALENDAR_REDIRECT_URI
ZOOM_CLIENT_ID
ZOOM_CLIENT_SECRET
ZOOM_REDIRECT_URI
```

Production callbacks:

- `https://meinangelplatz.top/api/auth/google/callback`
- `https://meinangelplatz.top/api/auth/zoom/callback`

Google Calendar API должен быть включён. Scopes: `openid`, `email`,
`calendar.events`, `calendar.calendarlist.readonly` (полные Google URI в OAuth).
Выбор календаря допускает только роли owner/writer. До явного выбора ничего не
экспортируется. После выбора все дела с датой попадают в выбранный календарь.
При первом импорте загружается интервал от года назад до двух лет вперёд,
затем используется incremental sync с пагинацией и восстановлением после 410.
Повторения Google импортируются отдельными вхождениями.

Zoom: General App, User-managed, Development/local test, строгий redirect URI.
Scopes: `meeting:write:meeting`, `meeting:read:meeting`,
`meeting:update:meeting`, `meeting:delete:meeting`,
`meeting:read:list_meetings`, `user:read:user`.
Приложения не публикуются автоматически; платные планы не нужны для OAuth.
Ограничения длительности встреч определяет тариф подключённого Zoom-аккаунта.
Google в режиме Testing ограничивает срок жизни refresh token; при истечении
интерфейс требует повторного подключения. Переход к публичной публикации требует
отдельного решения владельца.

`deploy/cloud_ops.py` принимает ровно шесть значений через приватный stdin,
проверяет callback origin и атомарно обновляет root-only env без вывода значений.
Перед запуском нужен checkpoint конфигурации и БД. Не запускайте `compose config`
без `--quiet`, не передавайте credentials в аргументах команд.

## Поведение и повторные попытки

Триггер PostgreSQL сохраняет изменения в отдельную очередь, не затрагивая очередь
Яндекса. Worker работает каждые 30 секунд. Ошибки провайдера не отменяют
сохранённые локальные дела. Acknowledge проверяет версию записи очереди.
Google использует детерминированные event IDs, PATCH и ETag; поля участников и
conferenceData сохраняются. Если одновременно изменена локальная запись,
локальная очередь имеет приоритет перед полученной удалённой версией.

Zoom создаётся только по явному запросу. Meeting ID и join URL сохраняются,
изменения даты/времени обновляют ту же конференцию. Неопределённый результат POST
не повторяется автоматически: worker ищет созданную конференцию по служебной
метке. Если подтвердить результат нельзя, нужен ручной разбор вместо дубля.
Обычное отключение удаляет сохранённые токены и очередь, оставляя события и
конференции у провайдера. Сам grant также можно отозвать в настройках провайдера.

## Команды

- «Добавь встречу с Матвеем завтра в 15:00 в Google Calendar».
- «Создай Zoom-конференцию с командой на пятницу» — Гена уточнит время.
- «Создай Zoom-встречу завтра в 17:00 и добавь её в Google Calendar».
- «Перенеси эту встречу на 18:00» — обновляются связанные записи.

Контракт simple_llm: create_meeting принимает `calendar:"google"` и
`conference:"zoom"`. Эти поля сохраняются при уточнении времени и подтверждении
пересечений. Zoom создаётся перед экспортом Google, чтобы ссылка сразу вошла в
описание. Успешный внешний результат сообщается после проверки очереди.

## Проверки

Контрактные тесты используют отдельную PostgreSQL: OAuth state и защита от replay,
разделение аккаунтов, шифрование, refresh, создание Zoom и передача join URL,
повторные запросы, перенос, импорт и удаление Google, отключение.
Они не заменяют ручное согласие OAuth и проверки реальных API на домене.
После изменения выполняются Go tests/vet, frontend tests/build и security audit.
Миграция 005 добавляет отдельные таблицы и trigger; предыдущий backend совместим
со схемой для отката образа.
