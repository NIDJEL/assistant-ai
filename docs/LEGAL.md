# Правовые документы и подтверждения

Публичные страницы доступны без авторизации и при недоступности `/api/auth/me`:

- `/terms` — условия использования;
- `/privacy` — политика обработки персональных данных;
- `/personal-data-consent` — отдельное согласие;
- `/privacy-policy` — совместимый адрес политики из исходных документов.

Редакция от 20 октября 2026 года подготовлена по предоставленным владельцем
файлам `01_politika_pdn.docx` и `02_soglasie_pdn.docx`. Реквизиты оператора
перенесены из этих файлов; размещение основного VPS и PostgreSQL в России
подтверждено владельцем. Разделы исходного шаблона про Тильду, платежи,
проверку сайтов и генерацию документов заменены описанием фактических
функций Гены и используемых поставщиков.

Расположение основной базы в России не означает, что внешние сервисы
обрабатывают всё только в России. В политике отдельно описаны GigaChat,
Groq, Azure Speech, выбранные пользователем интеграции и доставка push.
Текст документов не подтверждает выполнение оператором уведомительных
или иных организационных процедур: их выполнение остаётся обязанностью
оператора в применимых случаях.

## Подтверждения

Две отдельные галочки изначально пусты. Первая подтверждает принятие условий
и ознакомление с политикой, вторая — отдельное согласие на обработку данных.
Оба подтверждения требуются для входа и регистрации по почте и через Яндекс.
Ссылки открываются в новой вкладке и не сбрасывают заполненную форму.

POST `/api/auth/register`, `/api/auth/login` и `/api/auth/yandex/start`
принимают вместе с остальными полями:

```json
{"terms_accepted":true,"personal_data_consent":true,"legal_version":"2026-10-20"}
```

Сервер отвергает отсутствующие подтверждения и устаревшую версию с HTTP 422.
После проверки учётных данных записываются идентификатор аккаунта, версия,
серверное время и действие (`email_register`, `email_login`, `yandex_login`).
Регистрация и запись подтверждения выполняются в одной транзакции.
Успешный вход через Яндекс фиксирует подтверждение, сохранённое в том же
одноразовом OAuth state и привязанное к браузеру. Отмена, ошибка и повторный
callback не создают подтверждений. Обычный GET запуска входа возвращает
пользователя на экран документов; GET для подключения календаря и связывания
существующего аккаунта сохраняет прежнее поведение.

Миграция `008_legal_acceptance.sql` добавляет таблицу и поле OAuth state,
не изменяя существующих пользователей, событий и сессий. Миграция не создаёт
подтверждений задним числом. Она совместима с предыдущей версией приложения.

## Обновление редакции

Изменяйте содержание в `web/src/pages/Legal/documents.tsx`, синхронно меняйте
`LEGAL_VERSION`, `LEGAL_DATE`, дату `<time>` в `LegalPage.tsx` и `legal.Version`
в `internal/legal/acceptance.go`. При необходимости обновите smoke-скрипты.
История Git сохраняет текст предыдущих редакций. Не редактируйте опубликованный
смысл документа без смены версии. При новой авторизации пользователь подтверждает
текущую редакцию; существующие сессии миграцией не прерываются.

Проверки: PostgreSQL contracts для отказов, серверного времени, атомарности и
OAuth; frontend unit tests; Playwright для обеих форм и всех документов,
недоступной auth API и экранов шириной от 320 px.
