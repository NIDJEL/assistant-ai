# Улучшения после TOP-10

26 октября 2026. Изменения в локальном рабочем каталоге; публикация, push и деплой не выполнялись. Цель — устранять причины низких оценок и проверять результат. Число «5» не подменяет измерение качества.

## Что реализовано

**Облачный смысловой поиск через работающий GigaChat.** `GENA_SEARCH_MODE=cloud` использует chat/completions для переформулирования запроса и оценки релевантности. Embeddings и локальная модель не требуются. В simple_llm с облачным провайдером это режим по умолчанию; `lexical` и прежний `hybrid` остаются отдельными настройками.

Сначала применяются тип, дата, статус и остальные структурированные ограничения. Каталог включает до 384 слов и 128 разнообразных названий из этого набора; повторяющиеся популярные записи не должны вытеснять редкие темы. До 40 кандидатов проходят дополнительную оценку; возвращаются до 10 подходящих результатов. В модель передаются временные номера кандидатов. Результат связан с пользователем, запросом и версиями всего отфильтрованного набора. Изменившийся набор вызывает резервный поиск с предупреждением. Кеш переформулировок разделён по пользователю, модели, запросу и каталогу, TTL 5 минут, до 1000 записей. На поиск выделено 8 секунд по умолчанию. Создание, изменение и удаление не вызывают этот дополнительный облачный путь; внешние поисковые вызовы выполняются вне транзакций записи.

**Личные серии встреч.** Поддержаны конечные серии с числом повторений или датой окончания, максимум 1000 встреч. До сохранения проверяются все будущие пересечения, включая пересечения внутри самой серии. Можно изменить или отменить отдельное повторение на произвольной исходной дате. Для часовых/минутных серий требуется точный исходный timestamp. В NLU это `changes.scope:"occurrence"` и `changes.occurrence:<Temporal>`; у PATCH — `edit_occurrence_at`. Исходное повторение исключается через `exdates`, отделённая запись хранит серверные `series_id` и `recurrence_id`. Повторное редактирование той же исходной даты обновляет ту же запись.

Родитель и отделённое повторение сохраняются вместе. Проверка переноса исключает только его исходный слот, сохраняя проверку других повторений той же серии. Удаление родителя удаляет его отделённые записи. Восстановление возвращает только записи, удалённые вместе с родителем; более ранние самостоятельные удаления сохраняются. Конфликт отделённой записи откатывает восстановление всей серии.

**Календарь и редактор.** `GET /api/events?expand=true&start=…&end=…` возвращает календарную проекцию повторений за период до 93 дней. Виртуальная строка сохраняет ID серии и отдельный исходный timestamp. Редактор явно сообщает об изменении одного повторения. Показаны границы серии и отдельная отмена. Частые личные напоминания группируются в одну строку на день с точным числом повторений, включая переходы часов. Это позволяет показать месячный календарь минутной серии без скрытого обрезания. Общий предел проекции — 10000 строк с явной ошибкой при превышении.

**Сбои и доставка.** Проверено аварийное завершение отдельного процесса до commit и после commit до получения ответа клиентом. Незавершённые записи откатываются; повтор сохранённого request_id возвращает сохранённый ответ без повторных эффектов. Проверено завершение worker после принятия payload шлюзом, до локального ACK: транзакция освобождается, повтор сохраняет notification_id. Это доставка как минимум один раз; принятие шлюзом не означает прочтения или гарантированной доставки на устройство.

Исправлена отправка последнего уведомления конечной серии после автоматического завершения. Отмена повторения блокирует уже поставленную в очередь старую отправку. Ручное завершение инвалидирует уведомление, сохраняя корректный replay при сохранении неизменённых полей.

**Multi-Action.** Для ошибки недословного `source` модель получает точный код и поле, сохраняя ключи, intents и atomic_group. Проверка исходных цитат сохранена; доступно не более одного исправления. В живом прогоне это устранило отклонение списка из-за изменённого моделью падежа.

## Измерения

| Проверка | Результат |
|---|---|
| Живой GigaChat + PostgreSQL, TOP-10 после исправления source | 10/10 сценариев, 16 реплик, 14 вызовов модели |
| Первый новый поисковый набор, до исправления разнообразия каталога | 24/30 запросов с релевантным результатом в первой десятке |
| Второй новый набор после фиксации реализации: 1000 записей, 30 новых тем | 26/30, MRR 0,867, Recall@10 0,600; p50 1988 мс, p95 2792 мс |
| Поиск по словам на том же втором новом наборе | 0/30; результат относится только к этим далёким перефразировкам |
| Linux Go + PostgreSQL с детектором гонок | 1384 теста/подтеста прошли, 10 opt-in тестов пропущены, 0 ошибок и гонок |
| React/Vitest | 226 тестов прошли |
| Chromium: будущая встреча → изменение одного повторения; Multi-Action на телефоне и с клавиатуры | 2/2 сценария прошли |
| Аварийное восстановление, повтор после ACK и последняя отправка серии | Проверены на одноразовой PostgreSQL |

Новые поисковые наборы синтетические и составлены внутри разработки. Второй набор содержит 30 новых пар «тема/запрос» и переиспользует 850 отвлекающих записей. Реализация и prompts зафиксированы перед его первым запуском; после результата по ним не настраивались. Это дополнительная проверка обобщения, а не слепой внешний тест или показатель всей пользовательской истории. Артефакты содержат SHA наборов и исходников.

Полный Linux `go test -race` и сводные результаты: [машиночитаемые доказательства](evidence/quality5_2026-10-26.json). Подробные результаты: [новый поиск](evidence/quality5_cloud_fresh_v2.json), [живой TOP-10](evidence/quality5_top10_live.json).

## Что пока не позволяет поставить 5 во всех категориях

- В новом поисковом наборе остаются четыре пропуска. Не проверен общий тест с конкурентами на одинаковых данных и условиях; превосходство по всем показателям не доказано.
- Серии с приглашениями пока отклоняются явно. Личные серии реализованы; это не поддержка общих исключений и ответов участников на всю серию.
- Нативная серия во внешних Google/Яндекс-календарях, её двусторонние исключения и изменение отдельных внешних экземпляров не реализованы этим пакетом. Существующая синхронизация ближайшей записи не выдаётся за такую поддержку.
- Общее изменение расписания серии с уже отделёнными исключениями отклоняется явно, чтобы не продублировать встречи. Переименование и правка отдельных повторений доступны.
- Разворачивание будущих повторений подключено к календарному интерфейсу. Все исторические и диалоговые фильтры ещё не переведены на полный поиск по экземплярам серии.
- Живая доставка всех внешних интеграций, голос на нескольких физических устройствах и развёрнутый выпуск этой версии не проверялись.

Поэтому этот пакет существенно закрывает прежние пробелы, но оценки 5/5 по всем направлениям пока не подтверждены.

## Воспроизведение

Нужны рабочая облачная конфигурация для live-проверок и отдельная тестовая PostgreSQL. Для проверок с защитой от обращения к чужой БД DSN должен использовать loopback и базу с `semantic_test` в имени.

```powershell
go test -count=1 ./...
go vet ./...
npm --prefix web test -- --maxWorkers=2
npm --prefix web run build
go run ./cmd/simple-smoke -mode live -postgres -input testdata/simple_llm/top10.json -output artifacts/quality5_top10_live.json
go run ./cmd/retrieval-eval -mode cloud -budget 8s -dataset testdata/retrieval/fresh_v2_events_1000.csv -qrels testdata/retrieval/fresh_v2_qrels.json -output artifacts/quality5_cloud_fresh_v2.json
```

В Linux с gcc дополнительно запускается `go test -race -count=1 ./...`. Playwright-сценарии: `web/e2e/meeting-series.spec.ts` и `web/e2e/multi-action.spec.ts`. Пропущенные opt-in live-тесты перечислены в сводке; пропуск не считается успешной живой проверкой.
