# Semantic evidence validation

Policy v2 сохраняет существующий pipeline: original message → exact Go fast path → ParsePlan → strict DTO validation → semantic evidence validation → Go grounding/calendar → preview/confirmation → executor. Production/VPS в этой работе не используются.

В `SemanticPlan.evidence` передаются пары `{"field":"changes.date","text":"послезавтра"}`. Пути относятся к исходному DTO; индексы исключений начинаются с нуля. Обязательный `text` сопоставляется с текущим original message через Unicode-aware `strings.EqualFold`, с сохранением пробелов и границ слов. `Таймер` совпадает с `таймер`, но `завтра` внутри `послезавтра` не считается evidence. Комбинируемые знаки и underscore входят в границу слова. Повтор обязательного field запрещён.

Централизованная `EvidencePolicy(field, operation, value)` в `internal/nlp/evidence_policy.go` разделяет поля на Required, OptionalNonBlocking и NotApplicable. В реестре 33 смысловых поля: 24 потенциальных ограничения mutation и 9 полей создания/представления/типа. Применимость определяется операцией; null, нейтральные status/kind=any и отсутствующее ограничение — NotApplicable. Например, для batch_update с конкретными значениями: 21 Required, 1 OptionalNonBlocking (kind, проверяемый через batch.scope), 11 NotApplicable. Для create: 0/9/24. Матрица основных операций: `artifacts/plan/policy-inventory.json`. Количество — по семействам полей, wildcard индекса исключения считается один раз; фактически заполненных полей в команде обычно меньше.

Для update/delete/complete/batch_* обязательна provenance пользовательских changes, target, filters и query. Для времени и временных объектов используется путь объекта, например `changes.time`, а не `.hour`. Для query target нужен `target.query`; для ordinal/last — `target.reference` (ordinal также допускает `target.ordinal`). Для batch нужен `batch.scope`. Для `filters.exclude` обязательны пути каждого значимого заполненного поля каждого исключения. Явные status=open/done и priority остаются обязательными. Нейтральный status=any не требует цитаты. Create/read-only evidence игнорируется как неблокирующее, включая дубликаты и несовпадение текста; strict shape validation и language grounding остаются обязательными. Произвольные придуманные create titles по-прежнему отклоняются, канонический «Таймер» допустим при reminder + schedule.delay.

Go сопоставляет канонические значения для пяти relative-day слов, явных weekdays с direction, ограниченного набора числовых задержек и сдвигов, числового времени, порядковых слов и явных статусных/приоритетных слов. Неоднозначное время изменения не получает дефолтного часа. Сдвиг «на два часа» и задержка «через два часа» проверяются раздельно. Нельзя использовать одно вхождение evidence одновременно для source period и destination date. Все даты и периоды по-прежнему вычисляет Go из normalized meaning.

Это ограниченная safety whitelist. Для прочих temporal types (например calendar_period и calendar_date) этот слой гарантирует source provenance; их полное семантическое соответствие остаётся задачей модели. Он не доказывает entailment произвольной русской фразы и не является универсальным NLU. Ошибки намерения или пропущенного ограничения за пределами whitelist по-прежнему выявляются end-to-end аудитом.

При mismatch, отсутствующем evidence или неподдерживаемом критичном clock/day/delay/shift команда отклоняется **до preview**. Выбрана clarification, без автоматического исправления и выполнения: даже точная каноническая поправка не даёт модели право самостоятельно записать другое значение. Старый pending очищается. Следующее «да» не авторизует предыдущий preview.

Новые проверенные pending содержат `evidence_version=1`. После перезапуска сервиса подтверждение использует сохранённый snapshot; старые pending без этой отметки в SemanticPlan-режиме требуют повторить команду. Точные slot/choice fast paths наследуют отметку только от проверенного pending. TTL, scoped repository lookup, stale snapshot checks и атомарная batch транзакция сохранены.

Второго LLM verifier нет: обычные запросы используют максимум один ParsePlan; подтверждения — exact fast path. Нулевое число verifier calls фиксируется отдельно. Локальная диагностика содержит только field/reason, без текста пользователя.

48 исходных adversarial tests сохранены; `TestPolicyAdversarialNoMutations` добавляет 20 cases с neutral any, подменой required proof через optional поле, case normalization, duplicate и exclusion kind. Все проходят strict decoder, настоящий service, временную SQLite и последующее «да». Дополнительно проверены отсутствие evidence, подстрока внутри слова, пропущенное исключение, старый pending, отзыв предыдущего preview и четыре исходных source/destination регрессии.

Новый DEV: `scripts/plan_policy_dev.py`, policy 60 conversations / 120 turns, context 50 / 140 плюс короткие pronoun references 6 / 12. Предыдущий reference DEV классифицируется отдельно. Search canonicalization удаляет только пустой title/changes/schedule; populated несовместимые значения отклоняются, kind/query не угадываются. Search target ordinal/last позволяет read-only выбор показанной записи; неоднозначные ссылки уточняются. Для ambiguous/refinement сохранён свежий поисковый контекст с прежними TTL/idle limits; v7 выявил непокрытый command search clarification path, описанный в `SEMANTIC_POLICY_V7_POSTMORTEM.md`. Evidence mismatch mutation очищает destructive pending.

Frozen v6 завершён и не переоценивается. Evaluator запрещает запуск audit v2/v5/v6, требует freeze-протокол для нового v7 и проверяет source/input/prompt/schema/evaluator до и после inference. Повторная запись frozen output запрещена. Работает только с disposable SQLite, независимо от DATABASE_URL.

Метрики: unsafe — изменения неожиданных ID/создания; wrong-value — реально записанные неправильные значения на разрешённых ID, включая незапрошенные изменения остальных полей, и неправильные значения создания. Безопасный отказ снижает accuracy, но не считается неправильной записью. Confirmed wrong-value — такие записи на точном подтверждении. End-to-end проверяет весь результат каждого хода, multi-turn — все ходы разговора, complex — все ходы категорий кроме `simple_*` (включая их продолжения). Latency по сетевым запросам публикуется отдельно от cached replay и fast path.

Исторические результаты v5/v6 сохранены без переоценки. Текущий отчёт: `SEMANTIC_POLICY_V7_REPORT.md`.
