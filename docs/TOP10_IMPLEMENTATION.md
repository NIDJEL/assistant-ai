# Реализация TOP-10 для Гены

Продолжение работы: [облачный поиск, личные серии встреч и аварийное восстановление](QUALITY5_IMPROVEMENTS.md). Ниже сохранён срез исходного пакета TOP-10; новые возможности и ограничения описаны в продолжении.


26 октября 2026. Изменения внесены локально в существующий Go/React проект. Исходные незакоммиченные материалы сохранены. Деплой и push не выполнялись.

## Что изменилось

| № | Направление | Реализация и проверка |
|---|---|---|
| 1 | Multi-Action | До пяти действий, зависимости, частичный результат, отдельные pending и повтор без дублирования. Проверены исходная реплика со скриншота, явные часы, цепочка create→complete и пять команд. |
| 2 | Регулярная проверка | Новый top10.json: 10 сценариев, 16 реплик; число/статусы шагов, конечные записи БД, отсутствие лишних записей и сохранение повторений. Fixture входит в go test. Подготовлен еженедельный и ручной GitHub workflow quality-live.yml с JSON-результатами и идентификаторами исходников/корпуса. |
| 3 | Repair и preflight | Один повтор генерации для невалидного ответа/ошибки бизнес-валидации; без генерации при сетевом сбое. Тот же исполнитель предварительно работает внутри откатываемого SQL savepoint. Внешняя синхронизация — после commit. Уточнения не считаются ошибками. Repair бизнес-валидации сохраняет тип действия и состав плана. |
| 4 | Повторения в основном NLU | Minute/hour/day/week/month/year через существующее ядро. Число 1–1000 либо включительная дата окончания. Последняя отправка сохраняется, серия останавливается. Изменение всей серии, отмена повторения и scope:occurrence для ближайшего личного повторения. Оно отделяется в запись; исходный anchor/count серии сохраняются. Карточки показывают число/дату окончания. |
| 5 | Время и дата | Часть суток для «в 8» и «полвосьмого» уточняется. Даты и точные задержки фиксируются до уточнения/подтверждения. Секунды сохраняются. IANA timezone восстанавливается после JSON; несуществующее время одиночной записи при DST вызывает вопрос. Для календарного повторения Go удерживает часы, выдуманные моделью без выражения времени в источнике. |
| 6 | Semantic retrieval | Настоящий GigaChat embeddings API, валидация векторов, cosine + RRF с lexical search. Cache изолирован по пользователю/модели/содержимому; устаревшие документы не получают старый score. Мутационные цели выбираются прежним способом. CLI и фиксированная разметка 20 запросов на 1000 CSV-записях. **Live embeddings заблокированы HTTP 402 аккаунта; прирост не подтверждён.** По умолчанию lexical, hybrid включается конфигурацией. |
| 7 | Атомарные группы | Явный atomic_group: общий preview, отдельное подтверждение, savepoint и проверка итоговых конфликтов. Невалидный последний шаг откатывает группу; соседний независимый сохраняется. Изменившийся snapshot требует нового подтверждения. Проверены конфликт создаваемых встреч, перенос с последующим удалением мешающей встречи, отмена и фиксация времени повторения. |
| 8 | Управление шагами | Список статусов, выбор ожидающего шага, отмена шага/группы и подтверждение. Кнопки отправляют key с серверным UUID-токеном; старый токен не меняет другой preview. Завершённые шаги повторно не выполняются. В старых ответах управление скрыто, во время запроса заблокировано. |
| 9 | Внешние статусы | Чат и история читают PostgreSQL outbox/link/delivery состояния Google, Zoom, Яндекса и web push. Различимы ожидание, повтор, ошибка, отключение и синхронизация. Доставка остаётся у существующих workers. Push accepted означает приём шлюзом; получение/прочтение не заявляется. Чтение статуса проверяет владельца и не отправляет данные. |
| 10 | Пределы и метрики | Ограничены бюджеты реплики/инференса/эмбеддингов, размер входа/JSON/state и число шагов. Есть diagnostics и безопасные production-счётчики без текста пользователя. HTTP write timeout учитывает бюджет реплики. Ошибка embeddings включает lexical fallback с предупреждением и паузой 30 секунд перед новым обращением к провайдеру. |

Fixture TOP-10: **10/10, 30/30 результатов шагов, 0 вызовов модели**. [Сводка и хеши логов](evidence/top10_verification_2026-10-26.json).

Последний полный live-прогон **GigaChat-3-Ultra + PostgreSQL**: **10/10 сценариев, 16 реплик, 14 логических вызовов, 0 repair, 30/30 результатов шагов**; p50 **1215 мс**, p95 **2557 мс**. Время сценариев зафиксировано на 2026-10-26T04:53:00+03:00, timezone Europe/Moscow. [Полный результат](evidence/top10_live_2026-10-26.json).

Повторные прогоны выявили исправленные ошибки: потерю IANA timezone после JSON и назначение моделью 09:00 без просьбы пользователя. Ещё один прогон потерял запрос из-за transport error, без изменений БД. [История прогонов](evidence/top10_run_history_2026-10-26.json) включает неудачи. Это разработочный регрессионный корпус, а не независимая оценка всей русской речи или одинаковый тест конкурентов.

Frontend: 226 unit-тестов и production build проходят. Отдельный Chromium-тест проверил ширины 1440/390/320 px, отсутствие горизонтального переполнения, выбор третьего шага клавишей Enter, точный токен/key и скрытие старых кнопок. В браузерной проверке ответы чата — fixture, auth/PostgreSQL — реальные тестовые. [Мобильный экран](evidence/top10_mobile_2026-10-26.png). Точные результаты и SHA логов указаны в evidence. Локальный -race недоступен: отсутствует gcc для cgo. Это не успешный race-прогон; существующий Linux CI выполняет go test -race -count=1 ./....

## Настройки и воспроизведение

```dotenv
GENA_SEARCH_MODE=lexical
GENA_EMBEDDING_MODEL=Embeddings-2
GENA_SEARCH_BUDGET=8s
GENA_TURN_TIMEOUT=45s
```

GENA_SEARCH_MODE=hybrid включает внешний read-only поиск. Бюджет embeddings — до 20 секунд, реплики — 1–120 секунд; стандартный бюджет NLU — 30 секунд внутри общего. Cache: до 6000 векторов, TTL 30 минут; semantic часть — до 2000 документов с предупреждением при превышении, lexical — весь отфильтрованный набор. Операция — до 64 KiB, запрос — до 2000 символов, план — до пяти шагов, state — до 1 MiB. Pending — 30 минут. diagnostics.duration_ms — время до commit; end-to-end latency измеряет CLI. Логические вызовы модели не включают внутренние HTTP retry транспорта.

```powershell
go test -count=1 ./...
go vet ./...
go run ./cmd/simple-smoke -input testdata/simple_llm/top10.json -output artifacts/top10_fixture.json
# Нужен локальный disposable TEST_DATABASE_URL; имя БД содержит semantic_test.
go run ./cmd/simple-smoke -mode live -postgres -input testdata/simple_llm/top10.json -output artifacts/top10_live.json
go run ./cmd/retrieval-eval -mode both -output artifacts/retrieval.json
npm --prefix web test -- --maxWorkers=2
npm --prefix web run build
```

Live workflow начнёт работать после публикации изменений и настройки GIGACHAT_AUTHORIZATION_KEY; при необходимости используется доверенный PEM GIGACHAT_CA_BUNDLE. Без ключа job явно отмечает пропуск. Расписание — понедельник 06:00 UTC, embeddings — отдельная ручная опция. Workflow не содержит деплоя.

## Ограничения

Повторяющиеся встречи/приглашения и изменение произвольного дальнего повторения пока не поддержаны. scope:occurrence относится к ближайшему повторению личной задачи/напоминания. В атомарной группе доступны личные создания и одиночные update/complete/delete; batch и социальные операции требуют отдельных сценариев. Локальная атомарность не распространяется на сетевые сервисы. Защита часов консервативна и может попросить уточнение необычной формулировки. Метрики стенда не доказывают превосходство над конкурентами на всех данных и устройствах.
