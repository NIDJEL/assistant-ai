# Проверки прототипа

## Автоматизированные

Локальная проверка: **73 Python-теста и 6 Node.js-тестов прошли**, Ruff не обнаружил ошибок. Голосовые тесты проверяют адаптер с подставными событиями, а не запись с физического микрофона.

Python pytest проверяет четыре обязательных действия и формулировки из задания, временные выражения, неверные даты/время, границы недели, уточняющий диалог, русский морфологический поиск/синонимы/опечатки, перенос и выполнение, подтверждение удаления, неоднозначный выбор, конфликты длительности и переход через полночь, параллельные записи, идемпотентность запросов, сохранение при перезапуске, независимость контекста сессий, импорт 1000 строк/повторный импорт/атомарный отказ, API-валидацию и окно напоминаний.

Node.js проверяет голосовой адаптер с подставным браузерным SpeechRecognition: финальная расшифровка отправляется один раз, промежуточная не отправляется, ошибки разрешения/сети/микрофона отменяют действие, повтор после ошибки работает, неподдерживаемый браузер вызывает подсказку, TTS выбирает русский голос и ограничивает длину ответа.

Ruff проверяет Python-код. GitHub Actions запускает обе группы тестов, сборку Docker, проверку Compose и HTTP smoke test контейнера.

## Практическая проверка

Локальный сервер запускается на Python 3.12, загружает 1000 строк CSV и отвечает через HTTP. В браузере проверяются создание напоминания, уточнение времени встречи, сохранение истории при обновлении, результаты поиска, фильтры, открытие схем и адаптивная компоновка.

## Границы проверки

Автоматизированные голосовые тесты используют подставной SpeechRecognition и не измеряют качество реального STT. Полный сценарий с живым микрофоном, разрешениями и облачным провайдером браузера необходимо проверить на устройстве демонстрации. Русский голос TTS зависит от ОС/браузера.

Ollama проверена на уровне HTTP-контракта, валидности JSON/дат и отказоустойчивости; реальная модель не запускалась в окружении разработки. Возможное качество её ответов отдельно не оценивалось.

Векторный поиск, повторяемость, календарные интеграции, несколько владельцев и фоновые push-уведомления не реализованы. Для открытого размещения необходим отдельный слой доступа и HTTPS.

## Docker на Linux

[GitHub Actions](https://github.com/NIDJEL/assistant-ai/actions/runs/38305704824) успешно выполнил установку закреплённых зависимостей, Ruff, 73 Python-теста, 6 Node.js-тестов, `docker compose config`, сборку образа и запуск контейнера. HTTP smoke test подтвердил доступность `/health` и главной страницы. Локально Docker не установлен; проверка контейнера выполнена в runner Ubuntu.
