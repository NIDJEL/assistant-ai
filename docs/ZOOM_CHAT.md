# Zoom в чате

Работающая User OAuth интеграция и сохранённые `cloud_event_links` используются без повторного подключения. Go добавляет `zoom_meetings` к ответу и сохраняет вложения в `dialogue_exchanges`; React использует `ZoomMeetingCard` и для ответов, и для автоматических сообщений. При загрузке истории карточки получают актуальные данные принадлежащей пользователю встречи и статус запуска. `simple_llm` поддерживает `conference:"zoom"` и `next:true` в list/search; ссылки и фактический статус модель не генерирует. Голос после расшифровки проходит тот же путь.

## Настройка Zoom Marketplace

1. В существующем General / User-managed приложении откройте **Development → Features → Access** (для опубликованной версии — соответствующее production-окружение).
2. Передайте **Secret token** в `ZOOM_WEBHOOK_SECRET_TOKEN` серверного `/etc/rhythm/production.env` (0600, root). Это отдельный секрет, не OAuth Client secret. Production Compose передаёт его только Go-контейнеру.
3. Включите **Event subscription** и добавьте endpoint `https://meinangelplatz.top/api/webhooks/zoom`.
4. Выберите события **Start Meeting (`meeting.started`)** и **End Meeting (`meeting.ended`)** для пользователей, разрешивших приложению доступ. Нажмите **Validate**, затем **Save**. При изменении прав Zoom может потребоваться повторная авторизация аккаунта.
5. Вручную запустите явно обозначенную тестовую Zoom-конференцию, связанную со встречей Гены. Проверьте автоматическое сообщение, затем вручную завершите конференцию и проверьте статус «Завершилась». Повторная доставка того же UUID не должна увеличивать число сообщений.

Обработчик поддерживает `endpoint.url_validation`: HMAC-SHA256 от plainToken. Все запросы, включая validation, требуют корректную HMAC-подпись `x-zm-signature` исходного тела и `x-zm-request-timestamp` в пределах ±5 минут. Тело ограничено 256 КиБ. Доступ к браузерной сессии для webhook не нужен; CSRF и авторизация остальных API сохранены.

Официальный контракт: [подписи и validation](https://developers.zoom.us/docs/api/webhooks/), [события Meetings](https://developers.zoom.us/docs/api/meetings/events/). Каждый запуск имеет отдельный UUID. Подпись повторной доставки проверяется по времени HTTP-запроса, а не по возрасту `event_ts`.

## Доставка и идемпотентность

Событие принимается только при совпадении meeting ID с сохранённой связью и `host_id` с текущим подключённым Zoom-аккаунтом. Неизвестные, удалённые и отключённые встречи не создают сообщений. Ключ запуска — `(user_id, meeting_id, run_uuid)`. Запуск, служебная сессия и сообщение сохраняются одной транзакцией под существующей блокировкой пользователя PostgreSQL. Поздний start после end того же запуска не оживляет завершённую конференцию и не создаёт уведомление.

Служебные сообщения сохраняются в той же таблице диалогов, отдельно от состояния пользовательской команды. `GET /api/chat/notifications` возвращает сообщения текущего пользователя (все непрочитанные и последние 100 прочитанных). `POST /api/chat/notifications/read` принимает явные UUID сообщений; прочтение сохраняется для пользователя на всех устройствах.

Доставка повторяет существующий механизм browser polling: каждые 5 секунд в видимой вкладке и при восстановлении фокуса/сети. Вне чата показывается ссылка с числом новых сообщений, в чате — индикатор «Новое сообщение» и действие «Прочитано». История открытого чата также обновляет статусы карточек. Отдельного сервиса или брокера нет. Это доставка в интерфейс; системные Web Push для Zoom эта функция не отправляет.

Без настроенной и проверенной подписки встреча остаётся «Запланирована», даже после времени по расписанию. «Идёт» появляется только после принятого `meeting.started`, «Завершилась» — после `meeting.ended`. Ссылка подключения разрешена только для HTTPS Zoom `/j/` или `/w/`; host-only `/s/`, `/start/` и `zak` запрещены. После завершения кнопка подключения отключена. Копирование сохраняет исходный join_url, включая необходимые непрозрачные параметры приглашения; отдельные пароли и OAuth tokens не отображаются.

Приложение пока использует единый часовой пояс аккаунтов установки `APP_TIMEZONE` (его же возвращает health); карточка форматирует дату в этом timezone. Отдельной настройки timezone в профиле существующее приложение не имеет.

## Проверки и откат

`go test ./...`, `go vet ./...`, `pnpm --dir web test`, `pnpm --dir web build`. PostgreSQL-контракт `TestZoomChatSignedWebhookLifecycleAndPersistence` проверяет подписанный HTTP webhook, конкурентные дубли, разные запуски, изоляцию, неизвестные ID/host, offline-сохранение, прочтение и end-before-start на отдельной тестовой базе. Новые исследовательские NLU-корпуса не нужны.

Миграция `006_zoom_chat.sql` только добавляет таблицу запусков, индексы и поля сообщений; предыдущая версия приложения продолжает работать с этой схемой. Перед deploy сохраните dump, production.env, старые image ID/tag и цель `/opt/rhythm/current`. Для отката верните env и symlink, затем пересоздайте только `app` предыдущим Compose. Базу и существующие интеграции сохраняйте.

Успешный синтетический тест с собственной подписью подтверждает обработчик, но не подтверждает доставку Zoom. Называть уведомления о фактическом начале проверенными можно только после реального запуска конференции и полученного webhook от Zoom.
